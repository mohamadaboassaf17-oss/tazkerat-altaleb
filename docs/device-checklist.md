# قائمة تحقق تثبيت PWA على الأجهزة الحقيقية — تذكرة الطالب

> تحقق يدوي من تثبيت التطبيق كـ PWA على أجهزة حقيقية. البناء تم عبر `vite-plugin-pwa` مع manifest: `dir=rtl`, `lang=ar`, `theme_color=#1e6f50`.

---

## 1. المتطلبات المسبقة — التقديم عبر HTTPS

> الهاتف الحقيقي لا يعتبر `localhost` سياقاً آمناً. تثبيت PWA (و Service Worker) يتطلب **HTTPS** على نطاق/نطاق فرعي حقيقي.

### الخيار (أ): نشر مجلد `dist/` على استضافة ثابتة

بعد البناء:

```bash
npm run build
```

انشر مجلد `dist/` على أي استضافة ثابتة (Netlify / Vercel / Cloudflare Pages):

- **Netlify:** اسحب وأفلت مجلد `dist/` في app.netlify.com/drop
- **Vercel:** `npx vercel --prebuilt dist` (أو ربط المستودع)
- **Cloudflare Pages:** `npx wrangler pages deploy dist`

### الخيار (ب): نفق محلي (Local Tunnel)

شغّل خادم المعاينة أولاً:

```bash
npm run build && npm run preview
# يعمل على http://localhost:4173
```

ثم أنشئ نفق HTTPS:

```bash
npx cloudflared tunnel --url http://localhost:4173
# أو ما يعادله من ngrok:
# ngrok http 4173
```

انسخ رابط HTTPS الناتج (مثال: `https://random-name.trycloudflare.com`) وافتحه على الهاتف.

**تحقق:** الصفحة تفتح بقفل 🔒 (سياق آمن) وليس تحذيراً.

## 2. أندرويد — Chrome

| # | الخطوة | التوقع |
|---|--------|--------|
| 2.1 | افتح الرابط في **Chrome** (وليس متصفحاً داخلياً مثل WebView لتطبيق آخر) | الصفحة تفتح |
| 2.2 | افتح قائمة Chrome (⋮) | يظهر خيار **«تثبيت التطبيق»** أو **«إضافة إلى الشاشة الرئيسية»** |
| 2.3 | اضغط «تثبيت التطبيق» | **يظهر مربع حوار التثبيت الأصلي** (أيقونة + الاسم «تذكرة» + زر تثبيت/إلغاء) |
| 2.4 | أكمل التثبيت ثم شغّل التطبيق من **أيقونة الشاشة الرئيسية** | يعمل **standalone**: شريط حالة النظام فقط، **بدون واجهة متصفح** (لا شريط عنوان ولا تبويبات) |
| 2.5 | فعّل **وضع الطيران** ثم افتح التطبيق من الأيقونة وأعد تحميل الصفحة (سحب للأسفل أو إعادة فتح) | **هيكل التطبيق (App Shell) يُحمَّل بالكامل** — الـ Service Worker يخدم الـ precache |
| 2.6 | تحقق من أيقونة التطبيق في مشغّل التطبيقات (Launcher) | أيقونة الـ manifest تظهر بشكل صحيح (خلفية `#1e6f50`) |

**فشل 2.3؟** غالباً manifest ناقص (أيقونة 192px/512px، `start_url`، `display: standalone`) أو لم يُسجَّل Service Worker. تحقق من `chrome://inspect` أو DevTools عن بعد.

## 3. iOS — Safari (إضافة إلى الشاشة الرئيسية)

> **مهم:** استخدم **Safari** حصراً. Chrome على iOS لا يدعم A2HS لـ PWA.

| # | الخطوة | التوقع |
|---|--------|--------|
| 3.1 | افتح الرابط في **Safari** | الصفحة تفتح |
| 3.2 | اضغط زر **المشاركة** (□↑) | تنفتح ورقة المشاركة |
| 3.3 | اختر **«إضافة إلى الشاشة الرئيسية»** (Add to Home Screen) | تظهر شاشة التأكيد |
| 3.4 | تحقق من الاسم المقترح | يظهر **«تذكرة»** (من `manifest.name`/`short_name`) |
| 3.5 | أكمل الإضافة ثم شغّل التطبيق من **أيقونة الشاشة الرئيسية** | يعمل **standalone**: بدون شريط عنوان Safari وبدون أزرار التصفح |
| 3.6 | فعّل **وضع الطيران** ثم افتح التطبيق وأعد التحميل | **هيكل التطبيق يُحمَّل** من الـ Service Worker precache |
| 3.7 | انظر إلى الأيقونة على الشاشة الرئيسية | **`apple-touch-icon`** يُعرض بشكل صحيح (بدون حواف بيضاء غريبة) |

**ملاحظة iOS:** لا يوجد مربع حوار تثبيت تلقائي — A2HS يدوي دائماً. لا يوجد أيقونة splash مضمونة إلا عبر `apple-touch-startup-image` (اختياري).

## 4. ملاحظات الانحدار — Service Worker قديم يخدم محتوى خاطئاً

**العَرَض:** واجهة تطبيق **قديمة** تظهر رغم أن الخادم يقدم نسخة جديدة (خاصة بعد تجربة مشاريع `localhost` متعددة على نفس المتصفح/الجهاز — Service Worker من مشروع آخر يتدخل).

**الإصلاح اليدوي:**

1. DevTools → **Application** → **Service Workers** → اضغط **Unregister** على الـ SW القديم
2. DevTools → **Application** → **Storage** → **Clear site data** (يشمل Caches + IndexedDB)

**أو الصق هذا المقتطف في Console (مرة واحدة):**

```js
navigator.serviceWorker.getRegistrations().then(rs => rs.forEach(r => r.unregister()))
  .then(() => caches.keys())
  .then(ks => Promise.all(ks.map(k => caches.delete(k))))
  .then(() => location.reload());
```

> أعد تحميل الصفحة بعد التنفيذ، ثم أعد التثبيت من الصفر (القسم 2 أو 3) للتحقق النظيف.
